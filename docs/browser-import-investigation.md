# Исследование существующей сессии браузера

5 ноября 2026. Исследован профиль Brave на этом компьютере: cookies выбранных
музыкальных сервисов, их сохранённые HTTP-ответы и публичные JS-модули. Значения
cookies, заголовки авторизации, подписанные ссылки, ключи и личные HTML-страницы
в документ не включены. Профиль браузера не менялся.

## Подтверждено на локальных данных

- В профиле Brave найдены действующие по сроку cookies VK и Яндекса. Это не
  доказывает, что сервер примет скопированную сессию: такой ответ нужно проверить
  отдельным запросом.
- Страница Яндекса — `/collection`. Aurora ранее открывала `/collection/tracks`;
  в её собственном кэше отсутствовали ответы API со списком коллекции.
- Brave получал `api.music.yandex.ru/landing-blocks/collection/playlist-with-likes?count=8`.
  Ответ содержит `summary.count = 24`, восемь полных объектов треков и
  `playlist.playlistUuid`.
- Затем браузер получал `/playlist/<playlistUuid>?resumeStream=false&richTracks=false`.
  Ответ содержит `trackCount = 24` и 24 записи с `id` и `albumId`, без названий.
- Публичный веб-клиент поддерживает `richTracks` и постраничное чтение плейлиста.
  Для недостающих метаданных он использует `POST /tracks`: FormData с повторяемым
  полем `trackIds`. Старое имя `track-ids` здесь не применяется.
- Реальные сохранённые ответы проверены новым C++-разборщиком без записи в
  пользовательскую медиатеку: краткий ответ — 8 метаданных из 24; полный — 24 ID.
- В сохранённых `/get-file-info` и `/get-file-info/batch` указан транспорт
  `encraw`, кодек `aac-mp4`. Это не готовый открытый MP3. В публичном коде
  проигрывателя есть также транспорт `raw`; его выдача этому аккаунту пока не
  проверена. Смена транспорта требует нового подписанного запроса, простая
  замена параметра в старой ссылке не подходит.
- Отчёт последнего сбоя VK содержит ошибку команды CDP до первого результата
  чтения страницы. Старый отчёт не сохранял имя команды, поэтому конкретная
  команда по нему не установлена. Музыкальные документы VK в обычном HTTP-кэше
  не найдены; публичные скрипты подтверждают `al_audio.php`, `load_section` и
  загрузку списка через объект плейлиста сайта.

## Что изменено в Aurora

1. Исправлен маршрут коллекции Яндекса. Прежняя ссылка `/collection/tracks`
   нормализуется в `/collection`.
2. В собственном браузере Aurora читаются JSON-ответы API Яндекса. По UUID
   запрашивается полный плейлист; ID дополняются метаданными партиями до 200.
   Запросы выполняются последовательно. Если браузер не отдаёт тело уже
   завершённого ответа, Aurora отдельно запрашивает блок коллекции в текущей
   сессии.
   Заголовки текущей сессии остаются в памяти и используются только для
   разрешённых запросов к API музыки. Порядок задаёт полный ответ плейлиста.
3. Краткий блок из восьми треков не завершает импорт полного списка из 24.
   При отказе API в авторизации частичный плейлист не сохраняется.
4. Cookies передаются через отдельные `Network.setCookie`. Отклонение
   необязательной cookie не прерывает остальные; отклонение cookies входа
   сообщается явно. Смена JS-контекста при запуске повторяется ограниченно.
5. Отчёт содержит этап команды, категорию сбоя, число принятых/отклонённых
   cookies и счётчики API. Содержимое сессии в отчёт не попадает.
6. Перед сохранением аудио проверяется декодирование первой секунды через
   FFmpeg. Одного ffprobe недостаточно: зашифрованный MP4 может сообщать
   корректную длительность, хотя его аудио не воспроизводится. Отдельный тест
   создаёт синтетический зашифрованный MP4 и проверяет отказ от его сохранения.

## Пределы проверки

Тесты используют воспроизведение форматов реальных ответов и подменённый
HTTP/CDP-транспорт. Свежий вход, запросы к аккаунту и воспроизводимость скачанных
файлов здесь не подтверждены: доступ к сети и локальным сокетам браузера
ограничен средой исполнения. К открытой личной вкладке нет подключения
управления. Поэтому результаты исследования кэша не являются успешной
сквозной выгрузкой аккаунта.

Для полного сохранения аудио Яндекса остаётся проверить выдачу обычного
аудиопотока через поддерживаемый сервисом `raw`. Скачивание `encraw` как MP3 не
считается решением. Для VK после исправления инициализации нужен свежий отчёт,
чтобы отличить отказ сессии от сбоя чтения списка.
