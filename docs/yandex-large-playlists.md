# Полный импорт больших плейлистов Яндекс Музыки

Исправлен путь, при котором виртуальный список страницы мог завершить импорт примерно на 200 видимых строках. Само достижение конца DOM-списка теперь не подтверждает полноту Яндекс-плейлиста.

Полный состав проверяется по API: `trackIds`, `trackCount`, счётчикам `pager`/`paging` и страницам. Поддерживаются обёртки `result.playlist`, числовые ID, строковые ID с альбомом и объекты ID. Максимальное объявленное число сохраняется на протяжении операции: ответ следующей страницы с `198` не уменьшает ранее полученные `2037`.

Страницы собираются по номеру, независимо от порядка прихода. Вторая страница не может стать полным списком, даже если пришла первой. Если доступна связка владельца и вида плейлиста, используется также API полного списка ID. После получения состава недостающие названия, исполнители и длительности запрашиваются партиями не более 200 ID. Порядок ответа метаданных не меняет порядок плейлиста.

Запросы последовательные. При временной сетевой ошибке, HTTP 408, 429 или 5xx выполняются максимум два повтора. Очередь приостанавливается до повтора; учитывается `Retry-After` с ограничением ожидания до 60 секунд. Начальный отказ сессии допускает один повтор для завершения инициализации страницы. Используется API-хост страницы (`.ru` или `.net`); при сетевом отказе возможен повтор через второй разрешённый хост. Вход пользователя не прерывается запросами API до завершения формы авторизации.

Счётчик и процент обновляются после каждой партии. Повтор той же страницы, пропавшие после трёх запросов метаданные, отказ сессии и истечение срока ожидания завершают операцию с ошибкой и диагностикой. Частичный список не передаётся на сохранение. Повторы отменённого импорта не запускаются позднее. Для больших Яндекс-списков общий срок ожидания ограничен десятью минутами.

Повторный полный импорт переиспользует записи прежнего DOM-импорта с адресами `/album/…/track/…`, сопоставляя их с API-адресами `/track/…`. ID библиотеки, оценки, история и локальные файлы сохраняются. Старые плейлисты пользователя автоматически не удаляются.

Для встроенного и внешнего браузеров используется общий код ограниченного JSON-запроса. Разрешены только известные HTTPS-хосты и маршруты API Яндекса. Отчёт ошибки содержит числа страниц, треков, подтверждение полного списка и статус HTTP; значения cookies и токенов в него не записываются.

## Проверка

Локальный сценарий использует 2037 искусственных треков и форму ссылки `/playlists/lk.…?ref_id=…&utm_source=mobile_ios`. Проверяются:

- 198 строк предпросмотра при полном манифесте на 2037 ID;
- 11 страниц, уменьшившийся счётчик на последующих страницах и приход второй страницы раньше первой;
- HTTP 429 с повтором, постоянное отсутствие метаданных, повтор страницы и отказ API при видимых 198 строках;
- отмена ожидающего повтора;
- дополнительный маршрут полного манифеста;
- повторный импорт поверх существующих 198 записей с сохранением файла, оценки и истории.

Итог: 20 QtTest-проверок прошли, web-скрипты и шесть тестов cookies прошли. Linux и Windows x64 собраны; Linux smoke-запуск завершился без QML-предупреждений. Windows-архив обновлён; запуск на реальной Windows в этой среде не проверен.

Логи: `build/yandex-final-tests.txt`, `build/yandex-final-tests-build.log`, `build/yandex-final-linux-build.log`, `build/yandex-final-windows-build.log`.

Живой плейлист по предоставленной ссылке инструменту просмотра недоступен. Проверки подтверждают перечисленные сценарии локальными ответами API; фактический размер и успешный импорт именно этого плейлиста здесь не подтверждены. После обновления нужно перезапустить Aurora и повторить импорт ссылки.
