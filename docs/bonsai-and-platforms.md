# Бонсай вокруг обложки и перенос на другие платформы

В сцене «Бонсай» экран прослушивания теперь показывает плотную зелёную крону над обложкой, древесный ствол и переплетённые корни по обеим сторонам изображения. Корни заходят на края картинки, сохраняя открытым её центр. Размер обложки учитывает место для кроны; корни привязаны к реальному прямоугольнику обложки, поэтому композиция сохраняется при изменении размеров окна. На остальных сценах сохраняется обычное расположение обложки.

Корни разделены на три связанных участка. Рост низкочастотной энергии и импульс удара дают толчок затухающей пружине; средняя часть и кончики следуют с запаздыванием. При сильном басе добавляется небольшая быстрая дрожь. При паузе, скрытии сцены, выключении движения и нулевой интенсивности движение сбрасывается. Интеграция выполняется небольшими шагами, чтобы задержка кадра не приводила к скачку или раскачке без ограничений.

Крона рисуется в кэшированный Canvas 768×360, корни — в шесть небольших текстур 128×256. Бас меняет трансформации этих текстур, не запускает перерисовку дерева. Смена палитры объединяется таймером 100 мс. Бонсай использует существующий таймер атмосферы и её видимость, собственного постоянно работающего таймера движения нет.

Исправлен параметр FFmpeg в `LibraryModel::extractCover`: `force_original_aspect_ratio=decrease`. Прежнее написание с подчёркиванием вместо `=`, `force_original_aspect_ratio_decrease`, приводило к ошибке фильтра и потере встроенных обложек при импорте.

## Что проверено

Linux, Qt 6.12.0: сборка приложения и тестового исполняемого файла прошла; `qmllint` не выдаёт диагностик при отключённых предупреждениях о глобальных контекстных свойствах. Оба набора `aurora_animations` и `aurora_animations_null` прошли. Дополнительно прошёл существующий тест редактирования метаданных/обложек и сохранения файлов.

Новые QML-проверки охватывают привязку корней к краям обложек размером 100, 180, 340 и 410 px, отклик на бас и затухание, задержку кончиков, остановку при выключении движения и паузе, устойчивость к долгому кадру и отсутствие перерисовки кроны от баса. В программном режиме — 25 записей QtTest вместе с подготовкой и завершением; в Null RHI пропускается отдельная проверка программной сферы.

Три запуска настоящего приложения: 1440×900 и 390×760 с движением, 390×760 без движения. Во всех — воспроизведение синтетического FLAC с настоящей встроенной PNG-обложкой, нулевая громкость, ноль предупреждений QML. Пользовательская библиотека не менялась: конфигурация, база и каталог музыки находились во временных папках. [Результаты проверки](performance/bonsai-validation-2026-11-05.json).

Полный C++-набор заново не запускался; предыдущие два падения тестов поиска Hitmo/Zaycev отмечены в [отчёте по анимациям](animation-performance.md).

## Windows

**Перенос реалистичен, готового проверенного EXE пока нет.** Основные части приложения написаны на Qt/C++/QML: интерфейс, SQLite, мультимедиа, Canvas и трансформации не привязаны к Linux. Linux MPRIS/DBus уже исключается из Windows-сборки условием в CMake. В менеджере зависимостей есть ветки `.exe` и `venv/Scripts`.

Qt 6.12 поддерживает Windows 10 x64 и Windows 11 x64, включая MSVC 2022. Для этого проекта практичная сборка — Windows Qt 6.12 с WebEngine и MSVC, затем упаковка Qt-библиотек, QML, мультимедийных компонентов и WebEngine-процесса через `windeployqt`. См. [поддерживаемые конфигурации Windows](https://doc.qt.io/qt-6/windows.html) и [развёртывание WebEngine](https://doc.qt.io/qt-6/qtwebengine-deploying.html).

Проверка установленного здесь Windows SDK остановилась при `find_package(Qt6 6.12)`: доступен MinGW Qt 6.11.1. В его целевом наборе также нет WebEngine. Версия проекта не понижалась. Это проверка конфигурации, не успешная кросс-компиляция.

Перед готовностью Windows-версии нужны проверка путей обложек с буквой диска/обратными слешами в `AlbumArt.qml`, путей к профилям браузеров в `BrowserCookieImporter`, разделителя PATH в `WebLoginManager` и наличие Python/FFmpeg/загрузчиков. В коде поиска профилей преобладают Linux-пути `.config`, `.mozilla`, Snap и Flatpak. Отсутствие готового автоимпорта браузерной сессии не означает, что интерфейс и локальное воспроизведение невозможно перенести.

## Android

**Интерфейс пригоден как основа, нынешний проект целиком ещё не готов к APK.** Главный блокер: `CMakeLists.txt` безусловно требует `WebEngineQuick`, `main.cpp` инициализирует Qt WebEngine, а `NativeBrowser.qml` импортирует QtWebEngine. Qt WebEngine поддерживает только Windows, Linux и macOS, Android и iOS в этот список не входят. Это ограничение не исправится установкой более нового Android SDK. См. [платформы Qt WebEngine](https://doc.qt.io/qt-6/qtwebengine-overview.html).

Конфигурация установленного Android arm64 SDK тоже остановилась на версии Qt: здесь 6.11.1, проект требует 6.12. Android Manifest и минимальный API 28 уже есть, но это не подтверждение готового мобильного приложения.

Для рабочего первого Android-варианта потребуется:

1. Отделить desktop WebEngine и запуск внешних браузеров от локального плеера, убрать их безусловные C++/QML-зависимости из мобильной сборки. Для веб-входа рассмотреть системный браузер/OAuth либо нативный Qt WebView. [Qt WebView](https://doc.qt.io/qt-6/qtwebview-index.html) рассчитан в том числе на Android/iOS; его ограничения наложения поверх QML нужно учитывать при проектировании окна входа.
2. Поддержать выбор музыки через Storage Access Framework. `ImportManager::importFiles` сейчас принимает только `isLocalFile()` и отбрасывает остальные URL, тогда как системный выбор документов Android возвращает URI документа, который нужно открывать через соответствующий провайдер. Для метаданных и обложек нужен мобильный вариант без внешних ffprobe/ffmpeg. [Документы и файлы Android](https://developer.android.com/training/data-storage/shared/documents-files).
3. Реализовать фоновое воспроизведение и медиасессию: в манифесте сейчас есть только INTERNET, службы `mediaPlayback` нет. Для продолжения воспроизведения в фоне Android предусматривает foreground service с соответствующими разрешениями. [Background playback](https://developer.android.com/media/media3/session/background-playback).
4. Предлагать только доступные на мобильной платформе функции загрузки. В `DependencyManager` yt-dlp, SpotDL и внешний FFmpeg для Android уже отключены; обычный запуск Python-процессов и доступ к чужим браузерным cookies переносить как есть нельзя.

Практичный первый этап — локальная библиотека, воспроизведение, очередь, обложки, эквалайзер и новый бонсай. Затем мобильные источники и вход. Узкое Linux-окно 390 px проверяет компоновку; оно не проверяет Android-файлы, фон, touch-события и реальную производительность телефона.

## iPhone

Qt поддерживает iOS, поэтому интерфейс и бонсай технически переносимы. Потребуются отдельная сборка через macOS/Xcode, замена desktop WebEngine, работа с документами и нативным жизненным циклом аудио. В репозитории нет проверенной iOS-конфигурации или сборки; iPhone не запускался. См. [мобильные платформы Qt](https://doc.qt.io/qt-6/supported-platforms.html).
