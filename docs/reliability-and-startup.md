# Импорт, загрузки и запуск — 5 ноября 2026

Последующее исследование ограничения в 45 записей, обновление интерфейса
и эквалайзер: [текущее обновление](studio-update.md).

## Подтверждённые причины

Свежий `diagnostics/import-vk.json` (10:55 UTC) показывает 31 принятую cookie,
нулевое число треков и `Runtime.evaluate / timeout` до подтверждения навигации.
Aurora ждала `navigator.userAgent` в ещё не готовом контексте пустой страницы.
Теперь используется [Browser.getVersion](https://chromedevtools.github.io/devtools-protocol/tot/Browser/#method-getVersion).
Отказ или отсутствие ответа на необязательный запрос метаданных через 1,5 секунды
освобождает навигацию. JavaScript страницы для определения User-Agent не нужен.

В предыдущем отчёте страница уже открывалась, но распознавались только 27 строк.
Публичные JS-модули текущего VK из HTTP-кэша Brave подтверждают новый контракт:
`MusicPlaylistTracks` получает `playlist.count`, `playlist.head`, `fetchNext`;
модель списка использует `fetchRest` и запрашивает следующие 20 записей.
Сборщик читает модель только через компоненты музыкального списка и использует
её обычную пагинацию. Учитываются вложенная прокрутка, владелец плейлиста,
обложки, длительности и признаки окончания загрузки. Неполный список не выдаётся
за все 1300 треков. Сбой отдельного отложенного компонента не обрывает чтение.
После полной загрузки порядок берётся из модели плейлиста, даже если первыми
на экране появились строки из середины списка.

## Получение аудио

- Подготовка yt-dlp, JavaScript-среды и пары FFmpeg/ffprobe запускается при
  необходимости автоматически в каталоге инструментов Aurora. Базовая установка
  не зависит от необязательного Spotify-загрузчика. Один этап ограничен 5 минутами.
- Поиск и скачивание используют одну явно выбранную JavaScript-среду. Управляемые
  FFmpeg и ffprobe должны быть настоящими исполняемыми файлами, а не обёртками,
  которые начинают скачивать компоненты во время проверки версии.
- При HTTP 401/403 для VK или Яндекса с сохранённой сессией Aurora один раз
  запрашивает новую ссылку. Циклического повтора старого URL нет.
- При ошибке включённый автоподбор последовательно проверяет YouTube и
  SoundCloud; Hitmo и Zaycev.net включаются отдельной настройкой. Автоматически выбираются только близкие
  совпадения с известной подходящей длительностью и версией. Для остальных
  остаётся ручной выбор. Очередь можно остановить и отключить в настройках.
- Современный Hitmo передаёт публичные `item.download` / `item.play` через React;
  они читаются у соответствующей записи. Учитываются HTTPS-аудиоссылки без
  расширения и сетевые ответы с аудио MIME. Проверка файла через ffprobe и
  пробное декодирование FFmpeg остаётся обязательной.
- VK не подставляет общую кнопку воспроизведения вместо отсутствующей нужной
  строки. Предзагруженное аудио до подтверждения запуска нужного трека не
  сохраняется под его метаданными.
- Итоговый файл дополняет существующую запись: ID, плейлисты, оценка и обложка
  сохраняются. Неудачная попытка отмечается как восстановленная после успеха
  другого источника.

Панель загрузок содержит обложки, отдельные ошибки, повтор, смену источника,
автоподбор и кнопку открытия отчётов. `diagnostics/downloads.json` ограничен
100 событиями: источник, этап, категория, ID и время. В него не записываются
сырой вывод загрузчиков, cookies, названия треков и подписанные URL.

## Запуск и интерфейс

Проверки версий вынесены из пути показа окна в QtConcurrent. Повторные проверки
кратковременно используют кэш по пути, размеру и времени изменения исполняемого
файла. Запрос на подготовку во время начальной проверки не теряется.
Рекурсивный подсчёт размера медиатеки также выполняется в фоне; результат для
старой папки игнорируется при смене библиотеки.

При запуске сохраняется `diagnostics/startup.json`: время инициализации Qt,
базы, аудиоплеера, сервисов, QML и первого кадра, без содержимого аккаунтов.
На изолированной копии базы с 70 записями и установленными инструментами:
Qt — 1 мс, база — 3 мс, аудиоплеер — 138 мс, сервисы — 139 мс,
QML — 371 мс, первый кадр — 402 мс. Это прогретый тест Debug / offscreen /
software; результат не является замером холодного запуска на обычном рабочем
столе или сравнением с предыдущей версией.

[Числа замера](performance/startup-2026-11-05.json).

Экран прослушивания оставляет одну большую обложку, атмосферу вокруг неё и
отдельную очередь следующих записей. Движение связано с реальным PCM-анализом
баса, энергии и ударов. Фон использует кэшированные текстуры и преобразования.
Выбор источника имеет закреплённые заголовок, поиск и действия; прокручиваются
результаты, включая узкое окно.

## Проверка и ограничения

Пройдены 62 проверки QtTest, Node-проверки веб-скриптов и Python-проверки cookies.
Проверены полная модель VK из 1300 записей, отсутствие JavaScript User-Agent
при запуске браузера, зависший ответ его метаданных, обновление ссылки после
403, переход YouTube → SoundCloud, Hitmo и Zaycev через подменённый транспорт,
отклонение фрагментов/неиграющего аудио и сохранение идентичности записи.
Скриншоты экранов прослушивания, источников, узкого диалога и загрузок получены
без предупреждений QML. Обе настольные сборки обновлены.

Запросы к реальным сервисам и управление открытой вкладкой не проверены:
среда запрещает создание даже локального сокета (`Operation not permitted`).
Исследован сохранённый кэш публичного клиента, а не живая вкладка аккаунта.
Подменённый транспорт подтверждает работу Aurora, но не доступность конкретной
записи у внешнего сервиса. Потребуется проверка обновлённой сборки в обычной
настольной сессии. Защищённые потоки не выдаются за скачанные файлы.
